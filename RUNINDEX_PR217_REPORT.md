## Cause racine

L'endpoint `store_chat_response` acceptait `user_id` comme paramètre query string sans aucune vérification d'identité. FastAPI injectait directement la valeur fournie par le client dans le document inséré en base. Tout appelant pouvait donc passer n'importe quel `user_id` (celui d'un autre utilisateur, une valeur forgée) et créer des entrées `chat_messages` sous l'identité de cet utilisateur.

Il n'existait aucun middleware d'authentification sur cette route.

---

## Correction

### Principe appliqué

```
AVANT :  CLIENT user_id → store-response → chat_messages
APRÈS :  AUTH → authenticated user_id → store-response → chat_messages
```

### Patch (backend/server.py)

```python
# AVANT (vulnérable)
@api_router.post("/chat/store-response")
async def store_chat_response(user_id: str, message_id: str, response: str):
    """Store a response generated by client-side WebLLM"""
    await db.chat_messages.insert_one({
        "id": message_id,
        "user_id": user_id,   # ← valeur CLIENT
        ...
    })
    return {"success": True}

# APRÈS (corrigé)
@api_router.post("/chat/store-response")
async def store_chat_response(
    message_id: str,
    response: str,
    user: dict = Depends(auth_user),   # ← auth obligatoire
):
    """Store a response generated by client-side WebLLM.

    The owning user_id is resolved exclusively from the authenticated JWT;
    any client-supplied user_id is not accepted (A35 — P0 security fix).
    """
    user_id = user["id"]   # ← valeur SERVEUR uniquement
    await db.chat_messages.insert_one({
        "id": message_id,
        "user_id": user_id,
        ...
    })
    return {"success": True}
```

### Changements

1. `Depends(auth_user)` ajouté — authentification obligatoire (401 si absent/invalide).
2. Paramètre `user_id: str` supprimé du contrat public de la route.
3. `user_id` résolu exclusivement depuis `user["id"]` (JWT décodé côté serveur).

## Isolation multi-user

### USER_A vs USER_B

**Démonstration :** `test_user_a_cannot_write_under_user_b`

```
USER_A (JWT user-a)
  → POST /api/chat/store-response?message_id=msg-isolation-1&response=injected&user_id=user-b
  → auth_user résout user["id"] = "user-a"
  → db.chat_messages : {"user_id": "user-a", ...}

USER_B
  → aucune entrée {"user_id": "user-b"} créée
```

USER_A ne peut jamais créer/modifier une entrée `chat_messages` attribuée à USER_B via `/api/chat/store-response`.
